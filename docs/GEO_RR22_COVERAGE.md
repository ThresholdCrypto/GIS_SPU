# Geo-RR22「覆盖关系判定」实证报告（候选集剪枝的前置）

> 状态：**前置实证（结论：当前口径下不可实现剪枝）**，2026-10-08。
> 对应任务文档 §10、`docs/GEO_RR22_DESIGN.md` §7 第 4 条。
> 代码②证据：`tests/test_geo_rr22_coverage.py`；口径出处：`geosot_work-master`
> （GB/T 40087-2021 参考实现）、`../geosot_work-master/out/codes.json`（课题样例产物）。
> 纪律：**本文件只写被复算或被实测的东西**；未验证的一律标"未决"。

## 1. 问题：剪枝要判什么

候选集剪枝只允许删掉"双方可证不相交"的码（任务文档 §10：近似不得进入精确路径）。
"可证不相交"最自然的载体是**覆盖关系**：

```text
covers(a, b)  ⇒  a 的格网单元（含高度层、时间区间）完全包含 b 的
¬covers(a, b) 且不重叠 ⇒ 可以剪掉
```

所以本报告要回答的是**一个判定问题**：在 64 位码上，是否存在一条能**无损**判定
"a 覆盖 b"的规则？如果不存在，剪枝就不能做——否则会静默丢真冲突。

## 2. 参照系：国标参考实现的覆盖规则（已复算）

`geosot_work-master/src/geosot_core.py` 的路线 B 编码（`geo_num`）是：
**2·L 位莫顿交错码左对齐到 64 位，低位补零**：

```python
# geosot_core.py
def geo_num_routeB(...):  return morton(r, c, level) << (64 - 2 * level)
def parent_geo_num(code, level, parent_level):
    return code >> (64 - 2 * parent_level) << (64 - 2 * parent_level)
```

于是覆盖 = **前缀**：`a` 覆盖 `b` ⇔ `a == b >> (64 − 2·L_a) << (64 − 2·L_a)`
（且 `L_a ≤ L_b`）。这条规则无损、可由整数移位实现，对 PSI 是零成本。

**实测（课题样例产物 `out/codes.json`，level 21，21973 条二维码）**：

| 检查项 | 结果 |
|---|---|
| 低 `64 − 2·21 = 22` 位是否全为零 | **21973 / 21973 全零** ✓ |
| `bytes16_hex` 高 8 字节是否等于 `code` | 2000 / 2000 ✓ |
| 产物里条数/层级 | `count=21983`，`code_level` 全为 21 |

前缀性质在**国标码上成立**，且被课题样例逐条印证。**这一半没有争议。**

## 3. 本项目口径：64 位码不是国标莫顿码

本项目的码布局是 `ir/values.py::GRID_CODE_BITS`：

```text
grid_code = X17 | Y17 | Z7 | L5 | Toff14 | Lt4      (= 64 bit)
GRID_CODE_LAYOUT = "X17|Y17|Z7|L5|Toff14|Lt4"
```

它是**字段切分布局**，不是莫顿左对齐布局。两者不可互推：

| 检查项 | 实测 |
|---|---|
| 用本项目 `decode_grid_code` 解课题样例码 | 得到 `L = 0 / 16`（**不是** 21）、`Z = 117 / 32`——即解不出真实层级 |
| 用本项目编码器往返课题样例码 | 逐条 `True`（往返无损，但**语义错**：L 字段不代表真实层级） |
| 产物里 3D 点码（`dim=3`, `uav_track3d.csv`） | 10 条，**88 位**（`≥ 2^64`），与二维 64 位码不同构 |

即：**国标的前缀规则不能套到本项目的码上**。第 2 节那条规则的前提
（2·L 位左对齐）在本项目布局下不成立。

> 这不是"实现 bug"，是**两套编码**。本项目文档反复强调过同一件事的代价：
> "布局必须与对端一致：PSI 走 CSV 交换这些 64 位码，布局不同**不报错、只静默算错**"
> （`ir/values.py` 模块说明、`GRID_CODE_LAYOUT` 的存在理由）。
> 本报告把它从"纪律"升级为"**已实测的跨编码事实**"。

## 4. 本项目口径下能否另立一条覆盖规则？——口径未定，不能

若设 `L` 是真实层级、`(X, Y)` 是该层级的**本级索引**，则覆盖可定义为：

```text
covers(a, b) ⇔ L_a ≤ L_b 且 X_a == X_b >> (L_b − L_a) 且 Y_a == Y_b >> (L_b − L_a)
              且 a 的高度层集合 ⊇ b 的高度层集合（PSI 已承担）
```

**但本项目没有声明 `(X, Y)` 是"本级索引"还是"某个共同分辨率的索引"**，
而两种口径给出的答案相反。证据是项目自己的示例：

| 出处 | 写法 | 含义 |
|---|---|---|
| `examples/altitude_band.py:25` | `x=21861, y=27702, level=15` | 21861 < 2^15 ✓（像"本级索引"） |
| `examples/altitude_band.py:30` | `x=21861, y=27702, level=15` | 同上 |
| `geosecure/compiler.py:90-95` | `x=21861, y=27702, level=9` | 21861 ≥ 2^9 ✗（**不是** 9 级索引） |
| `examples/vertical_conflict.py:18` | `x=21861, level=15` | 同一个 x 跨 9 级与 15 级复用 |

同一个 `x=21861` 同时出现在 `level=9` 与 `level=15` 上：若 `(X, Y)` 是"本级索引"，
9 级那组就装不下（超出 2^9），覆盖判定要用的 `X >> k` 也无从谈起；若是"共同分辨率索引"，
则必须先声明那个分辨率。**当前接入层没有声明，故覆盖规则不可定义。**

## 5. 结论与对剪枝的处置

| 结论 | 依据 |
|---|---|
| 国标码**有**可无损使用的覆盖（前缀）规则 | §2，参考实现公式 + 21973 条真实码全零实测 |
| 本项目 64 位码**不是**国标莫顿码，前缀规则**不适用** | §3，解码实测 `L=0/16 ≠ 21`；3D 码 88 位 |
| 本项目自己的覆盖规则**无法定义**，因为 `(X, Y)` 与 `L` 的口径未声明 | §4，同一 x 跨 9/15 级复用的示例 |
| **候选集剪枝不得实现** | 任务文档 §10："近似不得进入精确路径"；无规则的剪枝就是近似 |

**下一步（交由接入层拍板，不是本项目能单方面决定的）**：

1. 明确 `(X, Y)` 与 `L` 的口径，并把它写进 `ir/values.py` 的模块说明
   （与 `GRID_CODE_LAYOUT` 同级：能被打印、能被对拍）；
2. 口径定了以后，用本节同一套检查（前缀/移位）复算一遍，再谈剪枝实现；
3. 若要与课题侧（国标莫顿码）直接交换码，则需先统一码布局
   ——否则 `docs/GEO_RR22_DESIGN.md` §3 约束 1（跨方一致性握手）缺一环。

**本报告不做的事**：不实现 `covers()`，不改 `geosot_optimizer`，不把 `partition_grid_codes`
（只划分、不丢弃）与剪枝混为一谈。
