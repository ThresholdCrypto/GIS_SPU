# 威胁模型与诚实披露：参与方模型 / 信任边界 / 泄漏面

> 任务文档 §17。本文只描述**当前代码实际做了与没有做**的事，不是安全承诺。
> 运行时登记见 `backends/psi_backend/runtime.py`（`PSI_OP_LEAKS` / `reveals` /
> `result_semantics`）；结果策略见 `docs/PSI_RESULT_POLICY.md`；能力快照见
> `docs/PSI_CAPABILITY.md` 与 `docs/psi_capability_report_wsl.json`。

## 1. 参与方模型

- 当前执行链固定为**两方**（`PSI_RUNTIME_WORLD_SIZE = 2`；
  `PartyManager` 对第三方登记显式拒绝）。SPU 枚举里的 `ECDH_3PC` /
  `NPC` 族**不等于**本项目已支持多方——不得据此宣称。
- 双方按**半诚实（honest-but-curious）**假设使用：各自遵守协议，
  但会利用自己看到的一切（协议消息、私有输入、结果）推断对方信息。
- **本仓库不提供恶意安全**：不防御协议偏离、伪造输入、选择性中止等恶意行为。
  上游 libpsi 协议（ECDH / KKRT / RR22）的安全目标以官方文档为准，
  本仓库不转述、不宣称。
- `PROTOCOL_DP` 是**带噪**协议：会向结果注入/丢弃元素（实测漏报真实交集，
  见 `docs/PSI_CAPABILITY.md` §2）。它用于统计披露场景，**不得当精确求交**；
  `result_semantics` 显式标注 `noisy`，状态词记 `executed-noisy` 而不是 `verified`。

## 2. 泄漏模型：谁会看到什么

| 信息 | 去向 | 当前处置 |
|---|---|---|
| 交集**本体** | 接收方（`receiver_rank` 指定；默认 0） | 协议标准语义，**不随结果策略改变**；逐算子登记在 `PSI_OP_LEAKS` |
| 交集**基数** | 接收方 / 广播路径 | `Intersects` 由基数推导布尔；基数本身已在接收方可见 |
| 私有集合（非交集部分） | 不交给对方 | PSI 的设计目标（半诚实模型下） |
| 业务层暴露（PSI） | 由 `ResultPolicy` 控制 | `REVEAL_BOOLEAN / COUNT / INTERSECTION`；见 `docs/PSI_RESULT_POLICY.md` |
| MPC 输出面（`DistanceLE` / `WeightedSum` / `TemporalOverlap`） | 指定输出方（SPU 模拟下为调用进程） | 登记码 `output-only`：输出在指定输出方揭示，输入与中间值在半诚实模型下不进输出面；**不宣称零泄漏**，不建模按方隔离，不得默认广播（任务书 §十）；`REVEAL_VALUE` 数值档与 `REVEAL_BOOLEAN` 分列 |
| 输入规模 / 执行耗时 | 真实部署中的流量与时间侧信道 | 本仓库**建模**不到：进程内模拟不模拟网络观测者；真实部署需自行评估 |
| 参与方绑定（谁提供了哪份输入） | 编译输出 `parties` / notes / CLI | 本仓库只登记调用方**声明的**绑定；不证明声明为真 |

## 3. 信任边界（每一层保护什么，不保护什么）

| 层 | 保护什么 | 不保护什么 |
|---|---|---|
| 编译器 / 编排层（本仓库） | 布局握手（不一致前置拒绝）、预处理版本+指纹登记、结果语义与策略披露、规模/磁盘前置检查、临时文件权限 | 不隐藏“交集本体已交给接收方”这一协议事实；不改写语义；不做计算正确性的密码学证明 |
| PSI 协议层（libpsi / `spu.psi`） | 半诚实模型下除交集（及基数）外不暴露私有集合 | 不保证恶意安全；不隐藏交集本体 / 基数 |
| 文件系统层（本仓库加固，§18） | 临时目录 0700、键文件 0600、异常与进程退出兜底清理、自建随机目录 | 不是全盘加密：同机 root / 同用户其它进程仍可能读到落盘文件 |
| 运行节点层（部署方责任） | —— | 本仓库不做远程证明 / TEE；节点被控时输入与中间结果可被读取 |

## 4. 输入完整性

- 各方对自己的输入负责：本仓库**不能**证明对方提交的格网码就是它宣称的数据。
- 可做核对（已实现）：
  - 布局清单双向核验（`--input-layout`）：双方都声明且不一致 →
    `LAYOUT_MISMATCH`，**进入 PSI 前拒绝执行**；只声明单方 = 无法核对
    （如实标注，不假装通过）；
  - Geo-RR22 预处理指纹（`fingerprint_grid_codes`）：双方各持一份，供审计对拍
    （注意：当前指纹**只登记、不强制校验**，见 `docs/GEO_RR22_DESIGN.md` §7）。
- 规模与磁盘前置检查在写文件**之前**执行（单方键数上限与余量，见 §9）；
  重复键在 RR22 / KKRT 会导致协议直接失败（实测，见
  `docs/BENCHMARK_PROTOCOL.md` §4），执行路径默认先去重。

## 5. 结果真实性与带噪披露

- `verified` 只对“与明文参考一致”成立；带噪协议记 `executed-noisy`——
  两类结果不混用（`result_semantics` 三档：exact / approximate / noisy）。
- `Contains` 的子集判定默认走 MPC 基数等值；退回明文时记
  `plaintext-fallback` 并整体披露，不做静默降级。
- 对拍口径不做“软化折算”（见 `docs/PSI_RESULT_POLICY.md` §4）：
  该失败的对拍必须失败。

## 6. 格网编码一致性（静默算错的防线）

- 布局单一来源：`ir.values.GRID_CODE_LAYOUT`（`X17|Y17|Z7|L5|Toff14|Lt4`）。
  跨方布局不一致时 PSI **不会报错，只会静默算错**——所以布局清单握手是
  执行前的强制核对点。
- L 位域 4→5 位变更后所有已生成的码都变（见 `docs/LOCAL_TEST.md` §4），
  历史样例数据必须重算，否则两方对不上。
- 本仓库样例仅为示例数据，**不得冒充真实数据验证**（§25-6）。

## 7. 协议参数一致性

- 协议 / 曲线 / `receiver_rank` / RR22 `low_comm_mode` 沿
  Planner → Compiler → Runtime → `PsiRunResult` **单链传递**（配置闭环）。
  复核方式：编译 JSON 的 `psi_runtime_config` 与每步 `protocol_params`、
  运行结果的同名字段逐一对照。
- 协议 / RR22 参数**不写进 Geo-IR**（§25-5）：业务语义与执行配置分离，
  换协议不改业务代码。

## 8. 日志泄漏

- libspu / libpsi 的原生日志会写 stdout / stderr；运行时在捕获路径过滤，
  并有“不落 CWD 日志”的回归测试（`tests/test_psi_backend.py` 日志卫生组）。
- 本仓库自身不对日志打印私有集合内容或交集本体；诊断信息只含
  计数、布尔、指纹与配置。

## 9. 临时 CSV 生命周期（§18）

- 每次运行自建**随机临时目录（0700）**；键文件与结果文件 **0600**；
  正常路径即时清理；异常路径与进程退出由 `atexit` 兜底
  （`_cleanup_active_workdirs`，有测试）。
- 写盘**之前**检查单方键数上限（`PSI_INPUT_MAX_CODES`）与磁盘余量
  （`PSI_DISK_HEADROOM_BYTES`），超限给出可读错误与分片建议。
- 敏感数据落盘说明：官方 PSI 是 **CSV 文件接口**（无内存张量接口——
  不得假设其存在，§18）。因此键集合在协议执行期**必然短暂落盘**；
  磁盘加密 / 隔离盘 / 专用节点属部署方责任。

## 10. 本仓库明确不做的安全承诺

- 不宣称恶意安全、不宣称防合谋、不宣称抗接收方反向推断
  （如从交集本体推断集合轮廓——这是 PSI 标准语义的一部分，由结果策略与
  部署设计缓解，不是本 MVP 能消除的）。
- 不做 TEE / 远程证明；不做密钥管理；不做网络层加密（真实部署需另行设计）。
- 不把“能力探测通过”表述为“安全达标”：能力探测只说明**能跑**。
