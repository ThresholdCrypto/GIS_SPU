## 0. 这一轮在解决什么

上一阶段把三个 PSI 族算子从 `backend-direct` 提升到 `verified`（真实
`spu.psi.psi_execute` 求交）。随后对**静态分析阶段**做了一次系统性探查，
发现的问题不在"功能缺失"，而在**安全判定可以被静默走错**：

> 只要算子或它的输入没能进入 Geo-IR，planner 就会依据"解析不到"落回
> 默认公开级别，把这个算子放进明文路径。这类错误不报错、不告警，只算错。

也就是说，**隐私泄漏的入口不在密码学层，而在前端识别层**。
本轮把这一类入口收口，并把结论钉进测试。

修复前基线：**219 项通过**。修复后：**279 项通过 / 0 跳过**。

## 1. 发现并修复的缺陷（8 项，全部有可复现证据）

| # | 缺陷 | 后果 | 位置 |
|---|------|------|------|
| 1 | 嵌套 `geo.` 调用被静默丢弃 | **隐私泄漏** | `frontend/analyzer.py` |
| 2 | 表达式实参解析不出→落回 PUBLIC | **隐私泄漏** | `frontend/analyzer.py` |
| 3 | 同名算子结果重名，`lookup` 解析到别人 | **隐私泄漏** | `ir/operations.py` |
| 4 | `compile_source(sensitivities=...)` 被静默丢弃 | **隐私泄漏** | `geosecure/compiler.py` |
| 5 | 中间结果不检查类型，"格网集合喂定点向量"无诊断通过 | 后端选错表征 | `frontend/analyzer.py` |
| 6 | `CellSetIntersect` 产出类型误标为 `Relation` | 掩盖第 5 项 | `geo_privacy/geo.py` |
| 7 | 代价位宽写死，与自身公式矛盾（K>1 时低估） | 报价失真 | `planner/registry.py` |
| 8 | `spatial_scope` 由粗糙下划线切分编造 | **假数据** | `frontend/analyzer.py` |

### 1.1 缺陷 1：嵌套调用被整条丢掉（最严重）

`_visit_statement` 只在 `node.value` **本身就是** `ast.Call` 时才处理，
任何嵌在表达式内部的 `geo.*` 调用从不被访问：

```python
return geo.intersects(geo.cellset_intersect(a, b), c)   # 旧：只有 1 个算子进 IR
return geo.intersects(a, b), geo.contains(c, d)          # 旧：0 个算子进 IR
xs = [geo.intersects(a, b), geo.contains(a, c)]          # 旧：0 个算子进 IR
```

丢掉的算子不会被报出来，而它的实参以**原始表达式字符串**留在 `inputs` 里
（`('geo.cellset_intersect(a, b)', 'c')`），`GeoProgram.lookup` 解析不到，
于敏感度判定只看到公开输入。

**修复方式（治因，不治表）**：识别改按整棵表达式树做，后序遍历，
内层算子先发射、外层算子引用内层的输出名；语句边界交给语句遍历，
保证每个算子恰好发射一次。没有变量承载的结果拿到**唯一且确定**的合成名
`geo_<op小写>_<序号>`。

修复后实测：

```
嵌套写法：CellSetIntersect(a,b) → Intersects(geo_cellsetintersect_1, c)
显式写法：CellSetIntersect(a,b) → Intersects(hit, c)
两者算子序列与 needs_crypto 完全一致
```

### 1.2 缺陷 2/3/4：敏感度判定的三条静默降级路径

- **表达式实参**：`geo.intersects(public_set, secret_set[:1])` 旧版把
  `secret_set[:1]` 当解析不到 → 只看到 `public_set` → 判 `plaintext-ok`。
  现在报 `GEO_INPUT_UNRESOLVED`（warning）并**按 SECRET 计入**。
- **重名**：`GeoOperation._default_output_name` 恒返回 `"<op>_0"`，
  导致两个同类算子同名；内层调用被重新命名后，外层实参仍指向同名输入，
  `lookup` 解析到的是**别的那一个**结果。实测：
  ```
  旧：第 3 个算子消费 SECRET 派生的 y，却按 x 的 PUBLIC 判定 → plaintext-ok
  新：geo_intersects_1 / _2 / _3 唯一 → 第 3 个判 secret
  ```
  另外 `if operation.output_name is None` 因该兜底**恒为假**，重命名分支是死代码。
- **显式声明被吃**：`_split_kwargs` 只转发 6 个 key，`sensitivities` /
  `type_hints` 被 `**kwargs` 接住后静默丢弃。现在显式接住、规范化
  （允许写 `"secret"` / `"CellSet"`），并且**未知参数直接报错**而不是丢掉。

### 1.3 缺陷 5/6：链式类型错误无诊断通过

方言表的 `returns` 记的是算子**供应给业务侧**的东西，而 `CellSetIntersect`
在 IR 里**产出**的是格网集合本体。旧版一律按 `returns` 记成 `Relation`，
且"中间结果"在类型检查里被整段跳过（注释写"交给后续阶段"）：

```
旧：cells = geo.cellset_intersect(a, b)
    geo.weighted_sum(cells, weights)      → CompactCellSet 喂 FixedPointVector，无诊断
    geo.temporal_overlap(cells, w1)       → CompactCellSet 喂 TimeInterval，无诊断
```

新增 `output_geo_type` 字段区分"产出"与"供应"，类型检查覆盖实参与了值的种类。

### 1.4 缺陷 7：代价位宽与自身公式矛盾

`WeightedSum` 档案写死 `b="16（8 位量化 × 8 位权重，留进位余量）"`，
而同一处的 `notes` 写 `b ≈ 8 + 8 + ceil(log2 K)`。K>1 时两者不等
（默认样例 K=3 → 应为 18）。现改为按 K 实算，并逐点验证与公式一致。

### 1.5 缺陷 8：编造 spatial_scope

旧 `_guess_scope` 取"第一个下划线之后的部分"：`public_set` → `set`、
`risk_factors` → `factors`。这是编造出来的作用域。`semantic` 里本就有
带命名约定表的 `infer_spatial_scope`（`route_A` → `A`，其余返回 `None`），
两处实现漂移。现委托给 `semantic`，删除本模块的粗糙副本。

## 2. 独立发现：诊断重复计数

`CompileResult.diagnostics` 把 `parse_result` + `plan` + `validation` 各并一次，
而 `validation` 本身已聚合上游（其 docstring 自称"唯一的编译前问题汇总面"）。
后果：同一问题在 `result.errors` 里翻倍，CLI 的"N 个错误"虚高。

实测（注入未登记算子）：

```
修复前：validation 里 BACKEND_OP_MISSING × 2，错误数虚高
修复后：× 1
```

同时发现 `planner` 与 `validate_program` 会各自报一次"算子未登记"，
措辞不同、位置相同。现按等价键去重（只在已知会重复的类别上放宽，
其余按"码+位置+消息"三重键），保留信息更精确的那条。

## 3. 高度层（Z）语义：**记录缺口，不做半成品**

格网码里 Z 占 7 位，编解码逐位对齐，但 **Z 不参与任何算子语义**：

```
同样 XY、只改 Z：
  z=15 -> 0x2ab29b0d87c80008
  z=99 -> 0x2ab29b0db1c80008
plain_intersects([z=15], [z=99]) == False
```

集合族算子是整数相等判定，因此"投影重合但高度层不同"会被判为不相交。
对本项目主场景（低空导航，GeoSOT-3D）这是实质缺口：低空空域分层管辖，
同一 XY 的不同高度带可能分属不同管理方。

**本轮决定不实现**。要落地需要先定义高度带的 Geo-IR 表示、确定带重叠下的
判据（区间比较而非相等比较）、明确它在 PSI 下如何表达（PSI 只做集合交，
带重叠需额外 MPC 比较）。在此之前不输出任何高度相关参数，
README 也不宣称支持三维冲突判定——**宁可留空，不给假数据**。

## 4. 对抗性验证

标准：**回退修复点 → 对应测试必须失败**；并且先确认变异本身真的改变了行为
（否则"没抓到"可能只是造了一个空变异）。

| 变异 | 行为改变 | 测试结果 |
|------|----------|----------|
| M1 只认 `node.value` 是直接 Call | 是 | 8 项失败 |
| M2 `input_sensitivity` 只统计可解析输入 | 是 | 3 项失败 |
| M3 `_split_kwargs` 静默丢弃未知参数 | 是 | 1 项失败 |
| M4 `output_name` 兜底判断（重名） | 是 | 1 项失败 |
| M5 `sensitivities` 不转发给解析阶段 | 是 | 4 项失败 |
| M6 `output_type` 用 `returns` 而非产出类型 | 是 | 2 项失败 |
| M7 中间结果跳过类型检查 | 是 | 4 项失败 |
| M8 `CellSetIntersect` 不登记关系 | 是 | 1 项失败 |
| M9 `validation` 不并入 `plan` 诊断 | 是 | 1 项失败 |
| M10 去重键放宽到只看 code（误删不同问题） | 是 | 1 项失败 |
| M11 `resolve_cost` 忽略 K（位宽写死） | 是 | 3 项失败 |
| M12 粗糙下划线切分（假作用域） | 是 | 2 项失败 |

M9/M10 第一次未抓到，原因是探针落在"无 plan 诊断"的场景上——即
**变异是空变异**。改用注入未登记算子的场景后确认缺陷真实存在并被捕获。
这条经验已固化：变异验证必须先证明变异改变了行为。

## 8. 一句话结论

本轮没有新增算子，也没有换协议；做的是把**静态分析层的隐私泄漏入口**收口：
让"算子被丢掉""输入解析不到""声明被忽略"这三类静默降级，
要么被正确解析、要么被显式报出、要么按最敏感级别保守计入。
所有结论都有可复现证据与对抗性验证支撑，SPU 源码未做任何修改。
