# 新隐私计算协议选型报告

> 目标：为"层面 3 之外"的协议扩展选择一个**外部开源实现**，其协议/功能
> **未被 SPU 0.9.5 底层实现过**（不改 SPU 源码）。
> 口径：本报告只写**核对过**的东西，注明来源；未核对的一律进 §6。
> 核对日期：2026-10-09。执行环境：WSL2 Ubuntu + conda `spu311`（py3.11）+ `spu 0.9.5`。

## 1. 选型约束（来自项目既有纪律）

1. **不改 SPU 源码**：`backends/psi_backend/__init__.py` 的设计边界写死了这条；
   wheel 为纯二进制（无 `.h` / `.cc`），也不具备改的条件。
2. 因此"新增协议"= 在 `backends/` 下新增一个**外部实现的接入族**，
   协议本体来自外部开源仓库。
3. 必须能**证明**该协议/功能不在 SPU 0.9.5 底层。
4. 必须可**三方对拍**（明文 / JAX / 新协议），容差口径明确。
5. 许可必须兼容（排除 AGPL 一类）。
6. 必须能在**同一环境**（Linux x86_64 / py3.11 / 现有 `spu311`）跑起来。

## 2. SPU 0.9.5 现有能力边界（核对结论）

| 面 | SPU 0.9.5 有 | 证据 |
|---|---|---|
| MPC 协议 | `REF2K / SEMI2K / ABY3 / CHEETAH / SECURENN`（**半诚实**） | `outputs/SPU隐私计算协议清单与协议扩展路径.md` §1.1 实测 |
| MPC 缺口 | 无 SPDZ / MASCOT 一类**恶意安全**协议 | 同上（`SWIFT` 在存根里是注释占位，未发布） |
| PSI 协议 | `psi_execute` + 7 协议：`ECDH / KKRT / RR22 / ECDH_3PC / ECDH_NPC / KKRT_NPC / DP` | `spu/libpsi.pyi` |
| PSI 输出形态 | `ResultJoinType` = `INNER / LEFT / RIGHT / FULL / DIFFERENCE`，**全部产出连线结果** | `spu/libpsi.pyi`（0.9.5rc2，6346 字节） |
| 非平衡 PSI | **已有**：`ub_psi_execute`（`UbPsiRole` SERVER/CLIENT + `MODE_OFFLINE*` 离线缓存 + `UbPsiServerParams.secret_key_path`） | `spu/libpsi.pyi`；本项目 `backends/psi_backend/capability.py:11` 已登记"另有 `ub_psi_execute`，本项目未用" |
| PSI 只出计数 | **没有**：`libpsi.pyi` 无 `reveal` / `cardinality` 相关字段（两个入口都写 join 结果） | `spu/libpsi.pyi` 全文核对 |

**三条可用的"真空档"**：① PSI 只出**基数**（PSI-CA）；② **交集内求和**
（intersection-sum）；③ MPC 的**恶意安全**族。

## 3. 候选与排名

| 排名 | 开源实现 | 协议/功能 | 许可 | 是否落入 SPU 真空档 | 接入成本 |
|---|---|---|---|---|---|
| **首选** | [OpenMined/PSI](https://github.com/OpenMined/PSI) | PSI-**Cardinality**（ECDH + Bloom/GCS，只回计数） | Apache-2.0 | ✅ 真空档 ① | **低**：`pip install openmined-psi`（cp311 manylinux 轮子，无需编译器） |
| 备选 A | [google/private-join-and-compute](https://github.com/google/private-join-and-compute) | **Private Intersection-Sum**（交集计数 + 关联值求和） | Apache-2.0 | ✅ 真空档 ② | 中高：Bazel + gRPC + Paillier |
| 备选 B（不建议） | [microsoft/APSI](https://github.com/microsoft/APSI) | Labeled / Unbalanced PSI（FHE） | MIT | ⚠️ 非平衡部分**已被 SPU 的 `ub_psi_execute` 覆盖**，只剩 labeled 算新 | 高：vcpkg + CMake≥3.25 + SEAL + ZeroMQ |
| 排除 | [encryptogroup/PSI](https://github.com/encryptogroup/PSI) | 多种 PSI | **AGPL-3.0** | — | 许可不兼容 |
| 排除 | [osu-crypto/libPSI](https://github.com/osu-crypto/libPSI) | 多种 PSI | 未声明（NOASSERTION） | — | 许可未定，不进选型 |

> 备选 C（仅当方向备案，本轮未核许可）：若要走 MPC 侧的真空档 ③（恶意安全），
> 候选是 MP-SPDZ 一类实现 SPDZ/MASCOT 的框架；但它自带一套 Python DSL，
> 与本仓库“Geo-IR → JAX → SPU”链路**不同构**，接入成本远高于前两者，
> 且其许可本轮未核实，故不列入正式排名。
>
> 备选 B 另有两个独立减分项（均来自其官方 README，已核对）：
> ① 其信任模型明确写"**响应不带认证**——任何能写接收方信道的一方都能让
> 接收方报出任意匹配"（confidentiality-only，非 integrity），涉密/低空管制
> 场景必须自备认证通道；② 其 `network::ZMQChannel` 不加密、不认证。

## 4. 为什么首选 PSI-Cardinality

**它是唯一一个能同时满足"可证明缺口 + 极低成本 + 补上本仓库已有缺口"的方案。**

1. **缺口可证**：SPU 的两个 PSI 入口都把 join 结果写给参与方。
   本仓库 `docs/PSI_RESULT_POLICY.md` §1/§3 已经写明这条硬伤——
   `REVEAL_COUNT` 的现状是"**接收方在协议内部仍然拿到交集本体**"，
   策略只改业务暴露，不改协议泄漏。
   接 PSI-CA 后，`protocol_leak` 这一栏**第一次能真的缩小**到"仅基数"，
   而不是换词描述。这是本仓库声明过、却一直没实现的那一格。
2. **缺口是"功能"而非"参数"**：`F_CA`（只回基数的理想功能）与 `F_PSI` 是两个
   不同的理想功能；OpenMined 的做法是让 client 在响应里只收到一个整数
   （`GetIntersectionSize`），服务器集合的非交集部分与"哪些条目命中"都不外泄。
   这与"给 ECDH-PSI 加个输出开关"不是一回事。
3. **不引入新工具链**：轮子已发布（`openmined-psi` 2.0.6，
   `cp39..cp313` 的 `manylinux_2_35/2_39 x86_64`），唯一依赖是
   `protobuf==6.30.2`。相比 APSI 的 vcpkg/SEAL 构建，这是数量级差异。
4. **顺手去掉一个既有约束**：libpsi 的 PSI **只吃 CSV 文件**
   （`SourceType` 只有 `SOURCE_TYPE_FILE_CSV`）；OpenMined 是
   **protobuf 内存消息**协议，格网码可以**直接在内存里过**，
   不需要落盘临时 CSV（本仓库 §18/§9 有整整一节在讲临时 CSV 生命周期）。

## 5. 已完成核对的接入要点

- **API（来自上游 `private_set_intersection/python/tests.py`，非推测）**：

  ```python
  import private_set_intersection.python as psi
  c = psi.client.CreateWithNewKey(reveal_intersection)   # False => 只回基数
  s = psi.server.CreateWithNewKey(reveal_intersection)
  setup = psi.ServerSetup();    setup.ParseFromString(s.CreateSetupMessage(fpr, len(client_items), server_items, ds).SerializeToString())
  request = psi.Request();      request.ParseFromString(c.CreateRequest(client_items).SerializeToString())
  response = psi.Response();    response.ParseFromString(s.ProcessRequest(request).SerializeToString())
  c.GetIntersectionSize(setup, response)   # 只回一个整数
  ```

- **数据结构**：`RAW` / `GCS` / `BLOOM_FILTER`。`fpr` 是**假阳率**参数 →
  GCS/BF 档的计数是**近似**的（上游测试自带 ±10% 容差），
  这正好对上本仓库 `result_semantics` 三档里的 `approximate`；
  要**精确**计数用 `RAW` 档。
- **安全模型**：半诚实、两方、服务器集合受保护 —— 与本仓库
  `docs/ADVERSARY_MODEL.md` §1 的假设**一致**（不需要改威胁模型）。
- **许可**：Apache-2.0（轮子内含 LICENSE，11357 字节）。
- **建议落位**：新增 `backends/psi_ca_backend/`，**不动**已稳定的
  `backends/psi_backend/`；先只服务**已有**算子 `CellSetIntersect` +
  `REVEAL_COUNT`，**不新增业务算子**（最小改动）。

## 6. 未验证项（诚实登记，不填推测值）

1. **本会话未能在 WSL 实跑**：`wsl.exe` 被沙箱拒绝（`E_ACCESSDENIED`），
   提权审批服务报基础设施错误。因此以下**均未实测**：
   `pip install openmined-psi` 在 `spu311` 环境是否可用；
   `protobuf==6.30.2` 硬钉是否与该环境其它包冲突；
   `_openmined_psi.so` 是否满足 glibc ≥ 2.35（Ubuntu 26.04 应当满足，但未跑）。
2. **轮子布局异常（已核对，需实测确认影响）**：该轮子把
   `site-packages/google/protobuf/...` 与 `site-packages/protobuf-6.30.2.dist-info`
   **整目录打进了 wheel 根**（70 个条目），安装后会多出一层字面
   `site-packages/` 目录。需在隔离 venv 或实测中确认不会污染环境。
3. **非平衡 PSI 的内核出处未核实**：只断言"上游 `libpsi` 已暴露
   `ub_psi_execute` 入口"，未核实其是否为 APSI 派生。
4. **PSI-CA 的接收方语义**需在实跑中确认：`GetIntersectionSize` 只回整数
   （上游测试如此），但"client 是否额外得知自己哪些条目命中"需实跑钉住。
